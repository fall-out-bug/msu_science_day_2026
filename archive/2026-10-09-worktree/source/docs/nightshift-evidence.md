# Координаты подтверждённых объектов для «Ночной смены»

`app/nightshift-evidence.js` экспортирует `window.NIGHTSHIFT_EVIDENCE` для девяти уже существующих случаев в порядке `s02, s08, s10, s01, s07, s11, s04, s06, s03`. Файл добавляет указатели к настоящим наблюдениям; изображения, измерения и исходный научный конвейер не изменены.

## Координаты изображения

Каждый кадр имеет размер **128 × 128 пикселей**. Координаты отсчитываются от нуля по центрам пикселей: `(0, 0)` — центр верхнего левого пикселя; `x` растёт вправо, `y` вниз. Центр поля — `(63.5, 63.5)`.

`tools/realdata.py:target_wcs` задаёт общую TAN-сетку ICRS с отрицательными обеими диагоналями CD-матрицы. Поэтому север уже сверху, восток слева. `stretch_rgb` и `png_bytes` сохраняют порядок строк массива; переворачивать `y` при отображении не нужно. Для HTML-указателя по процентам ширины/высоты используются `100 * (x + 0.5) / 128` и `100 * (y + 0.5) / 128`. Это также учитывает центр самого пикселя.

Генератор сравнивает все **27 PNG, встроенных в `app/data.js`,** с изображениями, заново полученными из соответствующих исходных массивов по общей шкале игры. Проверяется полное совпадение RGB-пикселей и размер, а не только сходство контактных листов.

### Движение

Основание — `assets/observations/motion-fields/_research/acquire_report.json`, поля `mover1.meas.measured` и `mover2.meas.measured`. Сохранённые измеренные RA/Dec преобразуются в пиксели общей сетки соответствующего случая. Генератор проверяет совпадение центра, масштаба и фотометрии отчёта с текущими наблюдениями, затем сверяет результат с сохранёнными `x/y` с допуском 0.001 пикселя. Эфемериды Horizons и опознание SkyBoT уже есть в исходном manifest; новые запросы и новые выводы об орбите не выполняются.

Точные координаты контрольных звёзд в этом отчёте не сохранены: там есть лишь суммарные результаты проверки сдвигов. Поэтому движущимся случаям `controls` не добавлены.

### Помехи

Генератор читает исходные `mskimg.fits` из локального кэша и их SHA-256 из `mask_evidence.sources`. Через WCS он сопоставляет четыре нативных пикселя, участвующие в билинейной интерполяции каждого игрового пикселя. Только игровые пиксели, поддержанные заданным битом маски, могут стать указателем. Из них выбирается максимум положительной разности между кадром с помехой и медианой двух остальных кадров.

Это **воспроизводимая точка на области помехи**, а не измерение её физического центра. Для длинного следа `s08` указатель находится близко к правому краю. Нельзя оценивать правильность любой другой отметки на этом следе по расстоянию до единственной точки `(122, 74)`. Бит 0 не различает самолёт и спутник; бит 7 обозначает возможное попадание частицы, не установленную физическую причину. В кадрах без соответствующей помехи стоят `null`.

### Фотометрия и сравнение

Позиции фотометрических целей берутся из RA/Dec исходного manifest и переводятся через ту же `target_wcs`, что использована для изображений. Это позиции источников/апертур, не заново измеренные центроиды по каждому PNG. Подтверждение изменения блеска находится в существующих `epoch_mags` или `photometry_alerce`.

Для `s06` сохранены реальные звёзды сравнения `(18, 52)` и `(107, 87)` из `weak1.aperture_check.comparison_stars`. Для `s01` цель `(60, 29)` и контроль `(98, 95)` взяты из `curated-provenance.json:normal_1.measured_sources`. `s01` служит сравнением почти постоянного потока на этих трёх кадрах; наличие указателя не делает звезду аномалией и не доказывает её постоянство во все времена.

Для `s10` и `s11` точные координаты контрольных звёзд не опубликованы в текущем manifest; новые контрольные точки не добавлены. Предварительные `qc_variable1.json` и `qc_weakmid1.json` относятся к другим выбранным эпохам и не использованы.

Для `s03` отмечается каталожная позиция сверхновой, свет которой смешан со светом соседа на расстоянии примерно 2.4″. Указатель не утверждает, что SN разрешена отдельно. В первом, майском кадре нет измеренного потока SN и он снят до обнаружения; поэтому для обнаружения объекта оставлен `null`. Общая предельная величина кадра не превращена в измерение или индивидуальный верхний предел цели.

## Воспроизведение и проверка

Из корня репозитория:

```sh
.venv/bin/python tools/prepare_nightshift_evidence.py
.venv/bin/python tools/prepare_nightshift_evidence.py --check
bun -e 'globalThis.window = {}; await import("./app/nightshift-evidence.js"); if (Object.keys(window.NIGHTSHIFT_EVIDENCE).length !== 9) throw new Error("Invalid evidence export"); console.log("Evidence browser export: OK");'
```

Генератор работает **только по локальным кэшам**, проверяет хэши задействованных научных кадров и масок, подготовленных архивов и manifest. Он не запускает импорт, не загружает наблюдения и не переписывает `app/data.js`.

`verification/nightshift-evidence/report.json` содержит хэши входных источников, PNG, параметры общей шкалы, координатный контракт и диагностику поддержки маской. `verification/nightshift-evidence/overlays.png` показывает все 27 исходных кадров: оранжевый указатель — цель, бирюзовые — опубликованные звёзды сравнения. Лист визуально проверен: движущиеся цели остаются на своих источниках во всех эпохах; фотометрические точки совпадают с источниками; отметки помех попадают на след и всплеск. `null` показан без искусственной цели.

Игровой интерфейс может сохранять личные отметки пользователя при `null`; такая отметка не должна получать оценку точности по отсутствующей координате. Для протяжённого следа единственный экспортируемый указатель также не задаёт область правильных ответов.
