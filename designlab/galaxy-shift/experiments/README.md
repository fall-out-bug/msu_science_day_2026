# Воспроизведение опыта CNN

Игра использует заранее рассчитанные результаты обучения свёрточной нейронной
сети (CNN). Таблица содержит все 2187 сочетаний меток семи изменяемых
изображений для каждой из 22 разрешённых упорядоченных архитектур: 48 114
обучений. Остальные два учебных изображения имеют фиксированные метки.
Архив за пределами основной четвёрки не добавляет изображения в этот опыт.

## Условия и результаты

`cnn-label-correction/protocol.json` фиксирует условия опыта.
`generate_cnn_experiments.py` использует NumPy-реализацию из
`cnn-prepare.py`: обучаются веса свёрточных слоёв, BatchNorm (если он есть)
и линейного классификатора. Перед расчётом проверяются SHA-256 исходных JPEG.
Девять учебных изображений отделены от трёх изображений знакомой проверки и
трёх итоговых изображений.

Схемы с одной и двумя свёртками имеют фиксированную инициализацию; для каждого
сочетания меток и каждой схемы обучение начинается заново с новым состоянием
Adam. Параметры: seed 20261008; центральный квадрат со стороной 75% от меньшей
стороны исходного кадра; изображение в оттенках серого 32×32 пикселя;
420 полнопакетных шагов Adam с learning rate 0.025; без аугментаций.
Архитектура содержит одну или две свёртки 3×3; после последней свёртки стоит
обязательная ReLU, а BatchNorm и Dropout (p=0,20) могут быть добавлены по
одному и переставлены. После первой свёртки двухблочной схемы всегда стоит
ReLU. Затем идут глобальное усреднение, линейный классификатор и softmax.

Текущий `--pilot` измеряет один запуск для указанной архитектуры и меток
`0121021`, без публикации таблицы. Он проверяет работу и длительность расчёта;
не служит основанием выбирать архитектуру или обещать ребёнку улучшение.

Итоговые изображения уже рассматривались авторами в предыдущей версии.
Они не участвовали в обучении, но не являются новым независимым научным
тестом. Один seed и три проверочных примера не оценивают надёжность модели.
Значения softmax — нормированные оценки модели для трёх категорий; без
калибровки они не являются вероятностями правильности.

## Проверки

Из корня репозитория, Python с NumPy и Pillow:

```bash
python3 designlab/galaxy-shift/experiments/check_constructor_math.py
python3 designlab/galaxy-shift/experiments/cnn-label-correction/check_constructor_table.py --require-full
python3 designlab/galaxy-shift/experiments/cnn-label-correction/check_reproduction.py
```

Первый скрипт проверяет конечными разностями вход, веса и смещения свёртки,
все семейства параметров каждой из 22 схем, а также независимые инварианты
BatchNorm и Dropout. Второй проверяет границы train/review/final, исходные
хэши, все 2187 ключей, точные строки, вероятности, argmax и счёт; после
полной генерации он также сверяет 21 шард с полным JSON. При наличии только
встроенной d1-r строки он завершается `BASELINE_PASS`, а не называет таблицу
полной. Для выпуска применяется `--require-full`: неполный набор завершает
проверку ошибкой. Третий скрипт независимо повторяет 66 обучений: исходные,
справочные и одинаковые неверные метки для каждой из 22 схем; он требует
точного равенства всех сохранённых научных полей. Это выборочная проверка
воспроизводимости, не повторное обучение всех 48 114 вариантов.

## Пересчёт

Следующие команды перезаписывают артефакты, поэтому нужны только при
намеренном изменении эксперимента:

```bash
# Один измерительный прогон без записи таблицы.
python3 designlab/galaxy-shift/experiments/cnn-label-correction/generate_cnn_experiments.py --pilot --architecture d2-r-d-bn

# Полная таблица.
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 MKL_NUM_THREADS=1 \
  python3 designlab/galaxy-shift/experiments/cnn-label-correction/generate_cnn_experiments.py --workers 6
```

Полная генерация сохраняет `cnn-label-correction/cnn-experiments.json`,
встроенный baseline `../cnn-experiments.js` для d1-r и 21 шард в
`../cnn-results/`. Браузер принимает только точный ключ и целый
провалидированный шард; при отсутствии или повреждении результата он выдаёт
ошибку, не запускает запасную модель. В источнике записаны хэши протокола и
расчётного кода. При изменении научных условий нужен полный пересчёт, а не
обновление метаданных старой таблицы.

После завершения каждой архитектуры генератор атомарно сохраняет её JSON в
`cnn-label-correction/checkpoints/` и публикует соответствующий baseline или
шард. Повторный запуск использует только checkpoint с теми же хэшами
протокола, `cnn-prepare.py` и генератора; несовпадающий checkpoint игнорирует.
Пока не готовы все 22 архитектуры, полный JSON не считается выпущенным.

Dropout в каждом новом обучении начинает одну и ту же фиксированную
последовательность масок. Поэтому при одинаковой форме тензора его случайная
маска не зависит ни от ключа изменяемых меток, ни от выбранной архитектуры;
сравнение состояний не получает дополнительного источника случайности.
Полная генерация запускает независимые CPU-процессы с одним BLAS-потоком
на процесс; число процессов задаётся явным `--workers`. В метаданных таблицы
сохранены количество обучений и сумма их длительностей. Их отношение даёт
среднее время одного обучения.
Это не время обучения в браузере и не обещание скорости на другом оборудовании.

`run_pilot.py` и `cnn-label-correction/PILOT-RESULTS.md` относятся к
историческому двухархитектурному пилоту и не являются командой или результатом
текущей таблицы. Терминологическая
проверка BatchNorm, Dropout и softmax с первоисточниками — в
`../../../docs/design-2026-10-08/evidence/cnn-layer-reference-review.md`.
Исторические опыты 1-NN и отдельное сравнение CNN сохранены в родительской
директории, но новый игровой маршрут их не использует.
