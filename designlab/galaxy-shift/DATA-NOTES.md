# Данные первого игрового среза

Пакет `2026-10-06-hubble-15-v3` содержит 15 разных объектов NASA/ESA Hubble:
девять для обучения, три для повторной учебной проверки и три для финала. Это
не экспертный каталог морфологий. Метки `гладкая`, `спиральная` и `вид с ребра`
— ясные для стенда визуальные категории; основание и источник каждого примера
лежат рядом в `data.js` и `provenance.json`.

Все JPEG — неизменённые screensize-файлы, скачанные с первичных страниц
ESA/Hubble. Они распространяются по [CC BY 4.0](https://esahubble.org/copyright/).
У каждой копии зафиксированы первичная страница, кредит и SHA-256. Игра не
называет эти снимки результатами Roman.

## Разделение и сценарная ошибка

Разные группы содержат разные объекты, а не варианты одного кадра. В обучении
один совместный пример, три обязательные метки ребёнка, две старые исправляемые
метки и три фиксированных примера. Порядок пяти редактируемых записей:

1. `child_m85`;
2. `child_ic5332`;
3. `child_ngc5023`;
4. `old_ngc3610`;
5. `old_ngc7090`.

Старые подписи намеренно испорчены в учебном сюжете: NGC 3610 получает
`spiral` вместо `smooth`, NGC 7090 — `smooth` вместо `edge_on`. Они не являются
ошибками ESA/Hubble и не выдаются за архивные метаданные. В базовом состоянии
`01210` сосед NGC 7090 даёт для NGC 4762 в проверочной подборке `smooth`; после
исправления NGC 7090 на `edge_on` ответ для этого же изображения становится
`edge_on`; счёт на этой повторной проверке меняется с 1 из 3 на 2 из 3. Это
причинный, заранее рассчитанный пример; другие ответы могут не улучшаться.

Проверочная подборка служит для демонстрации и была использована, чтобы выбрать
эту наблюдаемую сюжетную ошибку. Поэтому её метрика не является независимой
оценкой. Итоговые три объекта не использовались для выбора разбиения, категории,
ошибочных старых меток или метода; они открываются только в финале.

## Метод и воспроизводимость

`prepare-data.py` работает только с локальными изображениями, не ходит в сеть и
не использует GPU, модельный сервис или случайность. Для каждого JPEG берётся
центральный фрагмент 75%, он переводится в оттенки серого, уменьшается до 64×64
и нормализуется внутри изображения. Из него автоматически считаются центр
яркости, главные оси распределения света, радиальные и яркостные квантили;
1-nearest-neighbor выбирает ближайший учебный снимок по евклидову расстоянию
этих чисел. Это вычисленные из пикселей признаки, а не вручную заданные оценки
морфологии. Метод остаётся малым учебным примером, а не научной оценкой
классификации.

До просмотра результатов на review и final `feature-audit.py` сравнил на девяти
учебных объектах leave-one-out три фиксированных автоматических кандидата:
пиксели центральных 45% — 6/9, моменты яркости центральных 75% — 7/9, HOG
центральных 75% — 6/9. В v3 выбран единственный лучший результат — моменты
яркости. Это выбор по обучающим данным, не доказательство качества на новых
снимках. Проверочная и итоговая подборки в сравнении не участвовали; известный
финал предыдущих срезов от этого не становится независимой оценкой.

Возможны все `3^5 = 243` сочетания пяти меток. Скрипт заранее рассчитывает их
в `data.js`, включая ближайший учебный объект для каждого прогноза. Запуск:

```bash
python3 designlab/galaxy-shift/prepare-data.py
python3 designlab/galaxy-shift/prepare-data.py --check
python3 designlab/galaxy-shift/feature-audit.py
# Только после фиксации выбора: известные review/final-демонстрации
python3 designlab/galaxy-shift/feature-audit.py --evaluate
```

Для генерации и повторной проверки нужны Python 3, Pillow и NumPy; используемая
проектная виртуальная среда находится в `/home/zhuckoff/projects/msu/science_day/.venv`.
`--check` сверяет не только генерируемые файлы, но и локальные JPEG с отдельными
зафиксированными контрольными суммами допуска в `prepare-data.py`.

## Дополнительный опыт CNN

`cnn-prepare.py` рассчитывает два маленьких CNN на **одном** фиксированном
корректно подписанном наборе из девяти учебных объектов: один и два свёрточных
блока. Это настоящий CPU backpropagation на NumPy: обучаются и свёрточные веса,
и классификатор; 420 полных шагов Adam, seed `20261006`, без аугментаций и без
использования ответов review. В `cnn-data.js` записаны все три конкретных
ответа review, число параметров и начальная/конечная loss каждого опыта.

Оба варианта на этой маленькой демонстрационной проверке дали 2 из 3. Это не
основание объявлять их равными, хорошими или пригодными для научной
классификации: review уже используется в сценарии и содержит лишь три объекта.
Два блока не обещают улучшение.

```bash
python3 designlab/galaxy-shift/cnn-prepare.py
python3 designlab/galaxy-shift/cnn-prepare.py --check
```
