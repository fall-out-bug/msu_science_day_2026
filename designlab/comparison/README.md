# Мастерская неба: игровая смена

**Текущая игра:** `night.html`. Публикация на http://192.168.50.12:8081/
использует этот файл как главную страницу. Прежний стенд механик остаётся
в `index.html` исходников и на `/lab.html` в контейнере.

- 3, 6 или 9 исследований реальных участков. Режим 6 — основная смена.
- Обсерватория с Никой → карта звёздного неба → наведение на реальный участок →
  снимки в приборе → проверка → возвращение с результатом на доску.
  Ручная проверка открывает инструмент; пример ошибки улучшает отбор
  на другом поле. После финала можно продолжить.
- Клик/касание выбирают точку. Стрелки над canvas переключают кадры, пробел
  запускает сравнение. Список точек позволяет выбрать её кнопкой/клавиатурой.
- Результаты и примеры сохраняются локально на устройстве. Новая смена требует
  явного действия; журнал со снимками скачивается как HTML и открывается без игры. Звук включается по желанию.
- ZIP: `releases/night-shift.zip`; распаковать и открыть `index.html`.
  Все нужные ресурсы внутри, интернет не нужен. Автосохранение при открытии
  файла зависит от настроек браузера; при недоступности игра сообщает об этом.

`night-model.js` хранит правила кампании и объединяет научные модели,
`night.js` управляет переходами между комнатой, картой, прибором и итогом.
`world-room.js` рисует иллюстрированную комнату в Phaser; реальные снимки
появляются на мониторах и доске, индикаторы отражают сохранённые инструменты.
`sky-navigation.js` позволяет перетаскивать и масштабировать атлас,
а также управлять им стрелками и Home. `world-targets.js` связывает
координаты центров полей с архивными наблюдениями. Карта не подсказывает
ответ исследованию: её метка обозначает участок, а не изменившийся объект. Поиск неподходящим способом не завершает
обязательный вопрос о движении или свете. Пустые результаты на контрольных
участках сохраняются с объяснением ограничений. Обычная звезда не завершает
поиск усиления света или одиночного сигнала; вопрос о движении нельзя закрыть
поиском угасания. Старые наблюдения сохраняются, а ошибочно закрытый вопрос
при восстановлении смены открывается снова.

Журнал содержит настоящие снимки по датам с сохранёнными координатами
и измерениями. Карточка возвращает к тому же наблюдению. HTML-журнал содержит
встроенные изображения, выводы и ссылки на источники; его можно открыть
без приложения и распечатать. Кнопки продолжения и скачивания видны до длинного
списка результатов. Смена заканчивается в утренней обсерватории: персонаж
реагирует на собранный прибор, а наблюдения остаются на доске. Подробные
карточки открываются кнопкой «Посмотреть мою доску». Продолжение сохраняет
утро, новый игрок начинает ночью. Анимации не блокируют кнопки; пауза
останавливает рендер, reduced-motion оставляет статичные состояния.

## Ника и прогулка по небу

В комнате можно расспросить Нику о детстве в Карачаево-Черкесии, учёбе и первой
ошибке в наблюдениях. Это вымышленная героиня, а не биография сотрудника САО.
«Мой алгоритм» показывает три шага: правило, обучение на примере, проверка
на другом поле. В приборе постоянно видны ближайшее действие и кнопка помощи.

Панно открывает 12 зодиакальных созвездий. На карте появились линии и названия
88 созвездий, пять интересных мест и активность «Соединить звёзды Кассиопеи».
Нажимать можно прямо на карту; у активности есть кнопки для клавиатуры.
Прогулка не меняет исследуемый участок и не добавляет научных результатов.
Открытые места сохраняются отдельно. Карта — атлас всего неба, не расчёт
видимости из Архыза сегодня.

Три коротких рассказа объясняют роль машинного обучения в поиске астероидов
на снимках «Хаббла», работе BTSbot и открытии Kepler-90i. Две локальные
фотографии «Хаббла» сопровождаются подписями и указанием авторства.
Иллюстрация другой сверхновой явно отделена от исследуемых данных ZTF.
Источники и лицензии — `NIGHT-SOURCES.txt`, `exploration-provenance.json`.

`check-exploration-browser.py` проверяет реальные нажатия на canvas, порядок
звёзд, клавиатуру, восстановление прогресса, возврат к исследованию, подсказку
и мобильный экран. Скриншоты и отчёт — `evidence/exploration-*`.

## Что действительно обучается

`learning-model.js`: метод ближайших примеров, три признака (средняя скорость,
различие **векторов** скоростей, отношение яркостей пиков). Время и масштаб
изображения учтены. Масштабирование признаков вычисляется только на первом поле.
Модель видит все три даты; это не прогноз скрытого третьего кадра.

Игрок сравнивает уже проверенный зелёный след с оранжевой версией прибора
и отмечает несовпадающую точку. Ошибочная связь сохраняется как отрицательный
пример. Один подтверждённый след, четыре неподвижных примера и этот новый пример
меняют отбор. Крупные счётчики сочетаний исключены из игрового объяснения;
на другом поле видны конкретные следы с тремя настоящими снимками. При исправлении подготовленной реальной ошибки на другом поле
число принятых сочетаний меняется 991 → 2. Это сочетания 10 точек на трёх кадрах,
а не 991 независимый объект; маленький специально выбранный набор не измеряет
точность на небе. Из двух принятых версий одна не проходит геометрическую проверку.
Простое правило движения доступно рядом: преимущество ML перед ним не заявляется.
Исходный эксперимент и перенос различаются округлением исходных координат/пиков;
текущие числа считаются заново, не воспроизводятся из анимации.

## Данные и границы выпуска

`archive-data.js` добавляет четыре окна: усилившийся свет, слабое изменение,
контрольное поле и помеху. Суммарно девять разных окон; s04, контроль и полоска
сняты на общих экспозициях, что отмечено на экране. Для новых полей используются
обычные кадры, не подставленные разностные продукты. Фотометрия учитывает местный
фон, шум и контрольные точки. В SN-эпизоде шкала 100 → 34 относится к изменившемуся
свету относительно архивной опоры, не к полной светимости сверхновой.

Provenance: `provenance.json`, `brightness-provenance.json`, `launch-provenance.json`,
`archive-provenance.json`, `learning-provenance.json`. Воспроизводимые экспорты
требуют локальных научных FITS и Python-среды проекта; сырой архив не входит в ZIP.
`learning-reference.json` — независимые Python-числа для теста, не ресурс игры.
Источники и благодарности: `NIGHT-SOURCES.txt`.

Техническое прохождение проверяется `check-night-browser.py` (полное прохождение
3/6/9 через интерфейс) и `check-night-model.cjs`, `check-learning.cjs`,
`check-archive.cjs`. Отчёты — `evidence/night-*.json`. Билд собирает
`build-night.py`. `check-scene-browser.py` проверяет видимую смену света,
остановку настоящего canvas на паузе, reduced-motion и доступность финальных
действий. `check-world-browser.py` отдельно проверяет ручное наведение,
возвраты, фотографии на доске и доступность рабочих мест на разных экранах; публикация использует прежний отдельный Compose на 8081.

Цель фестивальной сессии — 10–15 минут. Длительность самостоятельного детского
прохождения и интерес детей пока не измерены. Прежняя нейтральная сборка
проверяла механику: считать её конечным визуальным решением было ошибкой.
Теперь используются ранее согласованные растровые обсерватория и Ника.
Некачественные декоративные SVG не возвращаются. Атлас NASA и выборка HYG
встроены локально, сведения об источниках и лицензиях входят в ZIP:
`world-provenance.json`, `sky-provenance.json`, `world-art-credits.md`,
`vendor/SKY-CC-BY-SA-4.0.txt`. Карта — обзорная цилиндрическая проекция
с искажением около полюсов; для анализа всегда открываются отдельные снимки ZTF.

# Предыдущий стенд механик


Функциональный прототип рабочего места без декоративных иллюстраций.
Опубликован на **http://192.168.50.12:8081/lab.html#overview**.
Для автономного запуска открыть `index.html`; зависимости локальные.

## Игровой путь

1. На рабочем месте лежат два реальных снимка. Кнопка «Открыть снимки»
   раскрывает прибор внутри того же рабочего места.
2. Игрок чередует наблюдения, выбирает сместившуюся точку и проверяет прогноз
   по третьему снимку. Результат вычисляется по данным, а не по ключу ответа.
3. После возврата на рабочем месте остаются три наблюдения выбранной точки
   и вычисленный промах прогноза. Проверенный поиск можно добавить в прибор.
   Установка меняет статус, не повторяя измерение.
4. Во втором испытании игрок измеряет ослабление света в области SN 2023tyk.
   Два снимка и результат измерения также остаются на рабочем месте.
5. После установки обоих инструментов игрок запускает их на других участках.
   Прибор просматривает все детекции и вычисляет предложения. Третье наблюдение
   позволяет проверить предложение; пустой и ненадёжный поиск тоже можно сохранить.
6. После исследования двух разных участков можно завершить смену. Итог содержит
   сохранённые проверки и число подтверждённых изменений. Поиск можно продолжить;
   повторный просмотр не увеличивает счётчик.

Два инструмента — готовые проверяемые алгоритмы, собранные игроком в один прибор.
Это не обучение ML. Исторические роли BTSbot и SNIascore раскрываются в истории
сверхновой. Научные снимки и вычисления реальные. Декоративные SVG обсерватории
и Ники исключены из страницы и публикуемого контейнера.

Текущий результат — функциональный фрагмент. Полная фестивальная сессия,
привлекательность и самостоятельное прохождение детьми ещё требуют работы
и человеческого плейтеста.

## Навигация и сохранение

`journey.js` управляет маршрутами `#overview` (рабочее место по умолчанию),
`#opening` (раскрытый прибор в том же месте), `#tracking` (подробное исследование),
`#brightness` и `#launch`. `bench.js` показывает сохранённые измерения;
самостоятельного состояния прохождения у рабочего места нет.

Переходы и кнопка браузера «Назад» сохраняют результаты. Незаконченный расчёт
отменяется при уходе. Открытие записи не добавляет попытку. Результаты хранятся
в памяти вкладки; новая смена или перезагрузка страницы очищают испытания,
установленные инструменты и журнал. Новая смена возвращает к рабочему месту.

Первый эпизод содержит Amosov. Поле Gianni сохранено для самостоятельного
запуска. Истории известного астероида и сверхновой доступны после проверки;
открытие 2020 AV2 описано отдельно, со ссылкой на Caltech.

## Научные границы

Исходные массивы и превью — архивные данные ZTF / IRSA, происхождение и хеши
в `provenance.json`. Два поля содержат движущиеся источники: одно для испытания, другое для запуска; третий набор
с одиночным сигналом используется для проверки неопределённого исхода модели.
Это учебное слежение, без команд реальному телескопу. Наблюдения сняты в разные годы.

`model.js` вычисляет `frame[epoch] - amount * frame[0]`. Цвета условные: голубой —
положительная разность, оранжевый — отрицательная. Фиксированное усиление дисплея
8× применяется ко всем кадрам; научные значения не меняются. Без согласования
формы изображений звёзды могут оставлять остатки. Остаток не равен движущемуся объекту.

`tracking.js` использует слепые максимумы яркости каждого исходного кадра,
выделенные `realdata.detect_sources(k=5)`. Эталонные координаты/названия объектов
не входят в алгоритм. В радиусе 5 пикселей от клика выбирается измеренный максимум.
Неоднозначный клик требует уточнения. Совпадение первых двух положений в радиусе
2 пикселей считается неподвижным; прочие связи используют радиус 3 пикселя и
совместимость амплитуд в пределах фактора 3. Это фиксированная эвристика, не
фотометрическая модель и не ML. Переменность блеска, размытие и пропуски детектора
могут привести к неопределённому результату.

Линейный прогноз учитывает реальные интервалы дат. Выбор не читает пиксели или
детекции третьего снимка. Проверка ищет единственный максимум в радиусе 3 пикселей
от сохранённого прогноза и отклоняет совпадение с прежним неподвижным фоном.
На двух учебных полях расстояния от прогноза до измеренной точки: 1.09 и 1.57 пикселя.
Три положения поддерживают гипотезу движения, но не устанавливают орбиту, тип,
опасность объекта или факт нового астрономического открытия. Повторная попытка
помечается в данных как сделанная после раскрытия третьего кадра.

## Эпизод SN 2023tyk

В `brightness-data.js` входят два обычных и два настоящих разностных изображения
ZTF от 7 октября и 10 ноября 2023 года. Исходные FITS и их происхождение —
`assets/discoveries/`; новый экспорт проверяет все четыре SHA-256, калибрует поток
к нуль-пункту 25 и выравнивает сетку. Команда `.venv/bin/python
designlab/comparison/prepare-brightness.py` использует `tools/realdata.py` и
зависимости numpy, scipy, astropy, Pillow; сети и `app/data.js` не требует.

`brightness-model.js` выбирает измеренный максимум первого обычного снимка,
а затем суммирует свет в радиусе 4 пикселей с вычитанием медианного фона кольца
8–12 пикселей. Основное измерение — свет на **разностных продуктах ZTF относительно
архивной опоры**, а не вычитание второго игрового кадра из первого. Переключатель
изображений помогает видеть, но не меняет фотометрию и не оценивается.

Для выбранного максимума (65,64): разностный поток 552.42 → 185.88, отношение
0.33648. В интерфейсе это 100 → 34, с явным указанием относительной шкалы.
Здесь расположен неразрешённый свет SN 2023tyk и соседнего источника примерно
в 2.4 угловой секунды. Нельзя называть эти числа полной светимостью сверхновой.
У контрольной точки (23,64) общая яркость меняется примерно на −2.2%; её шкала
отдельно подписана как общая яркость. Для точек у края фон не помещается —
результат остаётся неопределённым, с объяснением причины.

Порог «заметно ослабло» требует надёжного обычного сигнала, начального разностного
сигнала выше 5 оценок шума, падения выше 5 объединённых оценок, не менее 35% первого
разностного потока и более 10% обычного потока. «Почти без изменения» требует
надёжного обычного сигнала, изменения общей яркости в пределах 10% и разностного
остатка обеих дат не более 5% первого обычного потока. Эти фиксированные правила
проверяют небольшой учебный набор; точность на обзоре не заявляется.

Оценка шума — `1.4826 × MAD фона × sqrt(N пикселей) × 3`, с эвристическим запасом
на корреляцию после выравнивания. Это не формальная доверительная вероятность;
систематика вычитания и различия PSF остаются. Полные условия —
`brightness-provenance.json` и `BrightnessModel.limits`.

Историческая координата **не участвует в выборе и измерении**. После реального
исхода `faded` отдельное сопоставление области с каталогом открывает историю
SN 2023tyk. В ней BTSbot выбирает цель для спектроскопии, а SNIascore классифицирует
полученный и обработанный спектр. Основание: [статья авторов, раздел V.1](https://arxiv.org/html/2401.15167v1#S5.SS1).
Игра не запускает эти сети и не выводит тип Ia из двух изображений. Спектр здесь
не показан; художественная вспышка подписана как иллюстрация. Успешное измерение
остаётся доступным из журнала даже после другой попытки. Возврат сохраняет обе
части исследования, общий сброс очищает их для следующего игрока.

## Вход через первое действие

`opening.js` показывает s02 и использует тот же `comparisonProbe` для выбора,
проверки, результата и журнала. Он не хранит отдельного ключа правильного ответа.
Клик по раннему снимку переносится на поздний только при единственном вычисленном
соответствии первых двух кадров. Неоднозначный выбор просит уточнение на позднем.
Третий кадр не отображается до завершения проверки.

Чередование меняет только видимый снимок каждые 1,4 секунды. Нет выдуманного
движения между реальными кадрами. Доступны ручное переключение, остановка и
числовой список точек для клавиатуры. Reduced-motion отключает автоматическое
чередование при входе; скрытая вкладка и переход останавливают таймер.
После успешной находки путь ведёт к установке инструмента, после ошибки —
к повторному выбору. Кнопка в углу возвращает к рабочему месту.
Новая смена также возвращает к рабочему месту. Возвращение кнопкой браузера не стирает находку.

Автоматические проверки подтверждают доступность действий, сохранение результата
на рабочем месте и вычисления. Они не доказывают желание ребёнка начать.

## Самостоятельный запуск

`launch-data.js` содержит ссылку на готовый s07 и новый экспорт трёх обычных
снимков ZTF отдельного поля (2018, 2021, 2024). `launch-provenance.json` фиксирует
SHA-256 исходников, выравнивание, калибровку и независимые Python-измерения.
`prepare-launch.py` воспроизводит экспорт из локальных FITS, без сети.

`LaunchModel.scan(caseObj, mode)` просматривает все измеренные максимумы:
- движение: первые два кадра, фиксированный прогноз; третий доступен только
  `verify`, после выбора предложения;
- свет: апертурный поток обычных изображений с местным фоном, устойчивые
  контрольные точки поля и диагностические пороги. Новое поле не содержит
  разностных продуктов ZTF, поэтому фотометрия здесь отличается от SN-испытания.

Движение на поле A даёт один кандидат; третий кадр подтверждает его с промахом
1,57 пикселя. Поиск ослабления на том же поле отказывается от вывода из-за
разброса контрольных точек. На поле B поиск движения не выделяет кандидатов,
а поиск ослабления находит одну область: поток 6215 → 3452, затем 5978.
Относительная шкала в игре 100 → 56 → 96. Третье наблюдение показывает восстановление
света; три даты не устанавливают период или физическую природу источника.

Порог ослабления требует падения не менее 35% после поправки на медианное
изменение поля и выше пяти диагностических оценок шума. В оценку входят
местный фон, запас на корреляцию и не менее 5% потока либо больший разброс
контрольных точек. Это эвристика, не формальная достоверность «пять сигм».
Повтор измерения первой пары — не независимая проверка; третья дата описывает
последующее состояние. Пустой поиск не доказывает отсутствие изменений вообще.

`launch.js` хранит отдельно предложения, открытое свидетельство и сохранённую
проверку. Смена поля или способа очищает текущий просмотр, но сохраняет журнал.
Завершение требует двух разных исследованных полей, а не двух заданных успехов.
Линейный прогноз и простая фотометрия не называются ML.

## Проверки

```sh
node designlab/comparison/check-model.cjs
node designlab/comparison/check-tracking.cjs
node designlab/comparison/check-brightness.cjs
node designlab/comparison/check-launch-model.cjs
python designlab/comparison/check-browser.py
python designlab/comparison/check-browser.py http://192.168.50.12:8081/lab.html
python designlab/comparison/check-navigation.py http://192.168.50.12:8081/lab.html
python designlab/comparison/check-shift.py http://192.168.50.12:8081/lab.html
python designlab/comparison/check-opening.py http://192.168.50.12:8081/lab.html
```

Для браузерной проверки нужен Python с `playwright` и установленный Chromium;
`PW_CHROMIUM` позволяет указать бинарник. На текущем ARM-хосте используется
`.venv/bin/python`, Node — `/home/linuxbrew/.linuxbrew/bin/node`.

Проверки покрывают вычитание, связь наблюдений, фотометрию и автоматический
поиск. Научный тест запуска проверяет SHA-256 архивов, независимые измерения
Python, отсутствие чтения третьего кадра при поиске и независимость результатов
от каталожных имён. Браузерные проверки проходят испытания, установку,
разные способы поиска, журнал, нулевые результаты, завершение, отмену таймеров,
клавиатуру и мобильную ширину 390px. Актуальные результаты и снимки — в
`evidence/`. Они подтверждают программное поведение, а не детскую увлечённость.

Данные поставляются готовыми. Локальный `prepare_data.py` относится к прежнему
научному конвейеру проекта и требует его архивов, кэша, `app/data.js` и научных
Python-зависимостей; для запуска и проверки этого приложения он не нужен.

## Отдельный контейнер

```sh
docker compose -f compose.comparison.yaml build web
docker compose -f compose.comparison.yaml up -d --no-build --pull never --no-deps web
```

Compose-проект `sd2026-comparison`, контейнер `sd2026-comparison-web-1`.
По умолчанию слушает `192.168.50.12:8081`; переменные `SD2026_COMPARISON_BIND_IP`
и `SD2026_COMPARISON_PORT` меняют привязку. Основная игра на 8080 — другой сервис.
Образ содержит только приложение и лицензии, Nginx запрещает кеширование.
Внешняя сеть для игры не нужна. Phaser поставлен локально, лицензии в `vendor/`.
