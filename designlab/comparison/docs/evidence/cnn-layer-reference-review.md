# Проверка терминов CNN-конструктора — 2026-10-08

Проверен текст раскрывающегося пояснения конструктора CNN в `game.js`.
Термины и заявленное поведение сверены с официальной документацией PyTorch;
реализация опыта остаётся собственной детерминированной NumPy-реализацией,
а не вызовом PyTorch.

| Объект | Текст игры и реализация | Проверка |
|---|---|---|
| BatchNorm | «нормализует значения по статистикам обучающего пакета; при проверке использует накопленные статистики обучения», есть обучаемые масштаб и сдвиг | Соответствует определению BatchNorm2d: статистики вычисляются по `(N, H, W)` для каждого канала, `gamma` и `beta` обучаемы; при оценке применяются накопленные оценки. [PyTorch BatchNorm2d](https://docs.pytorch.org/docs/2.14/generated/torch.nn.BatchNorm2d.html) |
| Dropout | При обучении случайно обнуляет 20% значений, остальные умножает на `1 / 0,8`; при проверке ничего не меняет | Соответствует `Dropout(p=0.2)`: независимая бернуллиевская маска, масштаб `1/(1-p)` при обучении и тождественное преобразование при оценке. [PyTorch Dropout](https://docs.pytorch.org/docs/2.14/generated/torch.nn.Dropout.html) |
| Softmax | Преобразует оценки классов в числа `[0, 1]` с суммой 1; выбирается наибольшее; число не гарантирует правильность | Соответствует определению Softmax: элементы находятся в `[0,1]` и по выбранной оси суммируются в 1. Последнее предложение — корректное ограничение интерпретации: нормировка не калибрует вероятность правильности. [PyTorch Softmax](https://docs.pytorch.org/docs/2.14/generated/torch.nn.Softmax.html) |

## Точная оговорка о дисперсии BatchNorm

В `cnn-prepare.py` и текущем опыте `np.var(..., ddof=0)` вычисляет смещённую
дисперсию обучающего пакета. Эта же величина обновляет `bn_var` с коэффициентом
0,1 и затем используется при проверке. Поэтому формулировка игры про
«накопленные статистики» точна, но реализация **не является численно
эквивалентной PyTorch BatchNorm2d**.

PyTorch BatchNorm2d тоже использует смещённую оценку для нормализации во время
обучающего прохода, однако в moving/running variance сохраняет несмещённую
оценку (`correction=1`). Это различие намеренно фиксируется здесь как свойство
данного NumPy-протокола, а не скрывается за названием слоя. Оно не менялось
после просмотра review/final: хэши исходника включены в таблицу, и изменение
потребовало бы полного пересчёта.
