# Рабочий стол разметки: визуальная проверка

Проверено 2026-10-09 в текущем локальном runtime `designlab/galaxy-shift/index.html` с Chromium 1234. Это экспертный осмотр интерфейса, не детский плейтест.

## Метод

Сценарий: `START` открывает пробный снимок. Для 1280×720 и 1440×900 использован обычный desktop viewport. Проверка 150% использовала CSS viewport 853×480 и `device_scale_factor=1.5`: это проверяет компоновку, которую получает браузер при 1280×720 и масштабе 150%, без искажения CSS-свойством `zoom`.

В первых двух кадрах фото находится слева; справа один связный блок «Ника и реплика» над единым выбором метки. Реплика и карточки не пересекаются. На 853×480 фото — 220px шириной, Ника занимает узкую колонку 68px рядом с репликой, а три класса помещены в один ряд. Кнопки «Увеличить снимок», «Открыть снимок» и «Перейти к разметке» полностью в кадре; горизонтальной и вертикальной прокрутки нет.

## Проверенные действия

Временный Playwright smoke (`/tmp/quest-contract.py`) прошёл:

- «Увеличить снимок» доступна сразу и увеличивает центр;
- щелчок по снимку сохраняет выбранный участок и увеличивает его; повторное действие возвращает общий снимок;
- «Попросить подсказку» переключается на «Вернуться к заданию» и возвращает исходную реплику с понятиями;
- пробная метка не меняет основные метки обучения;
- переключения не заменяют узел `.quest-scene`.

`node:vm.Script`, запущенный Bun 1.4.2, успешно скомпилировал `designlab/galaxy-shift/quest-scene.js`; `git diff --check` прошёл.
