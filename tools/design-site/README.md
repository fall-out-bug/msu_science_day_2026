# Публикация дизайн-документов

Каталог: **https://sd2026.beetles.family/design/**.
Игра остаётся в корне сайта, прежняя публикация с комментариями — в `/docs/`.
Источником нового каталога служат материалы `docs/`, зафиксированные в Git.

## Добавить или обновить материал

1. Сохранить документ в `docs/<тема-или-дата>/`. Для новой редакции сохранять
   различие между предложением, принятым решением и результатом проверки.
2. Писать текст в Markdown; схемы — блоками `mermaid` или отдельными `.mmd` /
   `.mermaid`. HTML-отчёты и интерактивные схемы также поддерживаются. Ресурсы
   хранить рядом, ссылки задавать относительно документа. Самостоятельный
   HTML со встроенными изображениями можно перенести из временного каталога.
3. Проверить сборку и соответствующие страницы в браузере. Зафиксировать
   изменения, открыть PR в `main` и дождаться workflow `Design documents`.
4. После слияния дождаться обновления `manifest.json`, проверить документ
   по публичному HTTPS и вернуть владельцу прямую ссылку. Автоматическое
   обновление происходит примерно за две минуты плюс время сборки.

Добавлять новый материал в ручной список не нужно. Публикуются все документы
и схемы в `docs/`; вложенные иллюстрации и свидетельства проверок доступны по
ссылкам, но не перегружают список основных документов. Структура каталогов
сохраняется: `docs/design-2026-10-18/publication.md` получает страницу
`/design/docs/design-2026-10-18/publication.html`.

Этот каталог публичный. Личные заметки, секреты, базы комментариев и сырые
журналы не должны попадать в `docs/`. Происхождение научных материалов и их
ограничения сохраняются. Публикация предложения не означает его принятие.

## Сборка и проверки

Нужен Python 3.12+ и зависимости из `requirements.txt`; существующая `.venv`
проекта подходит. Сборщик не требует запуска игры или научных расчётов.

```bash
.venv/bin/python -m pip install -r tools/design-site/requirements.txt
.venv/bin/python -m unittest discover -s tools/design-site -p 'test_*.py' -v
.venv/bin/python tools/design-site/build.py --source . --output artifacts/design-site --revision "$(git rev-parse HEAD)"
.venv/bin/python tools/design-site/check.py artifacts/design-site
```

Выходной каталог должен отсутствовать или быть пустым: сборщик не удаляет
существующие файлы. Для следующего предпросмотра выбрать новый каталог.

Локальная команда сборки читает рабочие файлы для предпросмотра. Публикация
всегда использует отдельный `git archive` точного коммита, поэтому незаписанные
изменения и случайные файлы рабочего каталога не попадают на сайт.
`manifest.json` содержит исходный коммит и SHA-256 опубликованных ресурсов.
Mermaid загружается из локального закреплённого набора, без внешнего CDN.
Исторические ссылки на исходники вне набора ведут на GitHub с точным коммитом.

## Устройство доставки

На Sparky пользовательская служба `science-day-design-publish.service`
проверяет `origin/main`; таймер запускает её примерно раз в две минуты.
`git fetch` обновляет только удалённую ссылку, не переключая рабочую ветку.
Получение публичного репозитория идёт по HTTPS без SSH-агента и ключей GitHub.
Сборка запускается только при изменении деревьев `docs/` или `tools/design-site/`.
Перед новой автоматической публикацией требуется успешный push-запуск workflow
`Design documents` для того же коммита `main`. Пока CI ожидает или завершился
ошибкой, служба сохраняет предыдущую публикацию и повторяет проверку позже.

Рабочий каталог доставки — `~/.local/share/science-day/design-site/`.
Публичные версии находятся в `published/releases/<commit>/`; ссылка `current`
переключается после проверки всех контрольных сумм. Nginx читает этот каталог
через read-only mount; alias `/design/` ведёт к `current`. Игровой образ,
телеметрия и комментарии при обновлении документов не перезапускаются.
Старые версии автоматически не удаляются, чтобы сохранить возможность отката.

Веб-контейнер использует `compose.public.yaml` вместе с
`tools/galaxy-release/compose.override.yaml`. Этот override сохраняет mount
документов при последующих выпусках игры. Конфигурация nginx входит в игровой
образ и не зависит от незаписанных изменений рабочего каталога. Переменная
`SD2026_DESIGN_DIR` переопределяет каталог `published` при переносе на другой хост.

Служба использует установленную копию `publish.py`, независимую от текущей
ветки разработки. После изменения самого механизма доставки переустановить
таймер; новые документы и изменения сборщика подхватываются из `main` автоматически.
Служба выполняет код сборщика из принятого коммита: изменения `tools/design-site/`
проверяются как код, а не только как содержимое документов.

## Первое подключение на существующем хосте

Только при авторизованной настройке публикации. Предварительно сверить
действующий игровой образ, nginx и адрес upstream, сохранить контрольные
суммы игры и исторических документов, идентификаторы сервисов комментариев
и телеметрии. В службе и ниже указан существующий upstream этого проекта.

```bash
.venv/bin/python tools/design-site/publish.py --repo . --sync-main
base_image="$(docker inspect sd2026-web-1 --format '{{.Image}}')"
base_tag="sd2026-public:design-base-${base_image#sha256:}"
docker tag "$base_image" "$base_tag"
design_image="sd2026-public:design-$(git rev-parse --short HEAD)"
docker build --pull=false -f tools/design-site/Dockerfile.web --build-arg "BASE_IMAGE=$base_tag" -t "$design_image" .
docker run --rm --network sd2026_default --entrypoint nginx "$design_image" -t
GALAXY_PUBLIC_IMAGE="$design_image" \
  docker compose -f compose.public.yaml -f tools/galaxy-release/compose.override.yaml \
  up -d --no-build --pull never --no-deps web
.venv/bin/python tools/design-site/publish.py --repo . --sync-main --verify-base http://192.168.50.12:8080
tools/design-site/install-timer.sh
```

Производный образ сохраняет все файлы работающей игры и меняет только nginx.
Первое подключение пересоздаёт только web, добавляя mount документов. После этого
проверить прежние страницы, сохранность сервисов, каталог, HTML-отчёт и Mermaid
по публичному HTTPS. Локальный HTTP не заменяет эту проверку.
Для работы таймера после выхода пользователя требуется включённый linger;
на текущем хосте он включён. Установщик требует уже доступный каталог.

## Диагностика и ручная публикация

```bash
systemctl --user status science-day-design-publish.timer
systemctl --user show science-day-design-publish.service -p Result -p ExecMainStatus
journalctl --user -u science-day-design-publish.service -n 20 --no-pager
systemctl --user start science-day-design-publish.service
curl --fail --silent --show-error https://sd2026.beetles.family/design/manifest.json
```

При ошибке сборки опубликованная версия сохраняется. Ошибка контрольной
проверки upstream возвращает предыдущее значение `current`; служба завершится
с ошибкой, доступной через systemd. Тихая подмена результата не выполняется.

## Откат документов

Сначала остановить таймер, чтобы он не вернул новую редакцию. Дождаться
завершения выполняющейся службы; процесс публикации защищён файловой блокировкой.

```bash
systemctl --user stop science-day-design-publish.timer
.venv/bin/python tools/design-site/publish.py --repo . --rollback --verify-base http://192.168.50.12:8080
```

Проверить публичную страницу и её исходный коммит. После исправления в `main`
включить таймер: `systemctl --user start science-day-design-publish.timer`.
Откат документов не переключает игровой образ.
Откат web на старый образ без маршрута `/design/` уберёт каталог с домена;
для сохранения каталога использовать образы с этой конфигурацией nginx.
